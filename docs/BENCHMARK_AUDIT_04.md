# Portfolio release audit — 0.4.0

The benchmark is a useful **experimental portfolio artifact**: original business
contracts, reproducible job consumers, constrained patch evaluation, calibrated
negative cases, supplementary real dependencies, a structured approval protocol and
English publication files with explicit licenses. Its value is demonstrated engineering
and inspectable methodology. Novel research, real SME adoption and agent superiority
are not established.

| Previous gap | Implemented response | Evidence / residual limit |
| --- | --- | --- |
| Shallow single-function fixtures | All 26 have business module + editable workflow, protected consumer/storage and two job inputs | 78 integrated checks within 232 total; repositories remain small and share a wrapper |
| Only one deliberately broken alternative | Two business mutations + publication mutation per scenario | 130 core calibrations; authored interventions are not empirical model difficulty |
| SQLite/stdlib only | Four PostgreSQL candidate profiles and two pandas/sklearn profiles | Separate 18 reference checks; no full migration/dialect/dbt/concurrency coverage |
| Approval only described | Auditor for scoped clarification, plan versions, binding, stale approval and reported edits | Scripted 26 valid/130 invalid logs; no authentication, semantic scoring or real dialogue trial |
| Maintainability unreviewed | Detailed internal reference inspection and reusable human rubric | AI-assisted author inspection, not independent human review or accepted-agent patch ratings |
| Publication/legal ambiguity | Apache 2.0 code and CC BY 4.0 records/docs; English card/protocol/archive | Publisher must supply actual Kaggle account/slug and perform authenticated upload |
| Reproduction could drift | Image digests, frozen dependency hashes, exact check-set validation, deterministic export, CI | CI is configured; remote run status must be observed separately |
| External review unavailable | Explicit disclosure in card, protocol and README | Remains open; do not fabricate reviewer consensus or real-company provenance |

A calibration problem exposed a warm-cache fixture that accidentally bypassed the
intended malformed response. The fixture now changes document content before testing
a bad classifier response. A PostgreSQL profile exposed a mutation neutralized by the
backend's aborted-transaction semantics; that profile uses descending event order to
exercise an actual regression. These repairs strengthen negative calibration without
weakening acceptance assertions.

Six public development and twenty public evaluation groups remain fixed. Variants and
common integration checks are correlated; report group-level results. The dataset and
source evaluator/references are public. Docker bounds cooperative submissions but
does not establish a tamper-proof judge. An approved event log cannot authenticate
actual approval or enforce filesystem writes by itself.

Publication wording: **"Original synthetic SME maintenance workflows with a reproducible
evaluation harness and calibrated reference/regression evidence."** Do not claim
observed real incidents, comprehensive corporate security, frontier-model efficiency,
sycophancy reduction or cleaner generated code. Those are future experiment questions.

Release evidence is in VALIDATION_04.md and docs/validation/*-04.json. Existing 0.1–0.3
reports are historical; their hashes/counts do not describe 0.4.0. The multi-agent
LangGraph implementation remains a next-stage project, with zero real model trials.
